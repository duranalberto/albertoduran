High-performance personal portfolio and publishing platform built with **Astro 6**.
Static-first architecture with SPA-like navigation and structured long-form content support.

---

## Overview

This project is designed to:

- Deliver excellent performance and SEO.
- Provide smooth internal navigation with Astro view transitions.
- Support standalone publications and nested vaults of related publications.
- Maintain clear architectural boundaries.
- Keep client-side JavaScript focused on progressive enhancement.

---

## Architecture

### Static-First Philosophy

The site is generated as static HTML. Build-time integrations process MDX content, render Mermaid diagrams, optimize assets, and minify HTML before deployment.

Client-side JavaScript is added only where it improves the experience:

- Theme persistence and light/dark switching.
- Article heading navigation.
- Mermaid diagram expansion and theme-specific assets.
- Atlas schedule enhancement.

This keeps the default content path fast, indexable, and resilient.

---

### SPA-like Navigation

The project uses Astro view transitions to provide smoother internal navigation while preserving the benefits of a static site.

Implementation rules:

- The shared document shell lives in `BaseLayout.astro`.
- Internal routes should keep header, footer, and navigation behavior visually stable.
- Browser-side scripts must tolerate Astro page swaps.
- Interactive behavior should be progressive enhancement, not a requirement for reading content.

---

## Tech Stack

### Core Frameworks

- **Astro 6** - Routing, static generation, MDX, image optimization, and integrations.
- **Tailwind CSS 4** - Utility-first styling and theme tokens.
- **DaisyUI 5** - Theme-aware component primitives.
- **Vitest** - Unit and integration tests.
- **Playwright** - Production-preview browser tests.
- **Cloudflare Workers Assets** - Static deployment target configured through `wrangler.json`.

## Routing

Routing is file-based and owned by `src/pages/`.

| Route | File | Description |
| :-- | :-- | :-- |
| `/` | `src/pages/index.astro` | Home page |
| `/profile/` | `src/pages/profile.astro` | Professional profile |
| `/404/` | `src/pages/404.astro` | Static 404 page |
| `/thejournal/` | `src/pages/thejournal.astro` | Journal index |
| `/thejournal/[...slug]/` | `src/pages/thejournal/[...slug].astro` | Standalone publications, vault roots, and nested vault publications |

The site uses trailing slashes, so generated canonical routes include the final `/`.

## Frontmatter Schema

Journal content is defined in:

```text
src/content.config.ts
```

| Field | Required | Description |
| :-- | :-- | :-- |
| `title` | Yes | Display title |
| `pubDate` | Yes | Publication date used for sorting |
| `updatePubDate` | No | Last update date |
| `description` | No | Card and metadata summary |
| `image` | Required for standalone publications and vault roots | Publication image; vault children can inherit the root image |
| `github` | No | Related GitHub repository URL |
| `tags` | No | Tag list; defaults to `[]` |
| `order` | No | Manual ordering value; defaults to `100` |

## Deployment

The production build outputs static files to `dist/`.

Cloudflare deployment settings live in `wrangler.json`:

- Asset directory: `dist`.
- Not-found handling: `404-page`.
- Worker name: `albertoduran`.

DNS, SSL, and production traffic are managed through Cloudflare.

---

## Guiding Principles

- Static-first pages before runtime behavior.
- Minimal client JavaScript.
- Directory-driven content behavior.
- Strict build-time validation.
- SPA-like navigation without a full SPA runtime.
- Clear separation of concerns.
